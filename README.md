# CS-300-Data-Structures-and-Algorithms

Federico Gabaldon

Portfolio Contents

Project One: Runtime and memory analysis comparing vectors, hash tables, and binary search trees.

Project Two: C++ course planner that loads course information, prints courses in alphanumeric order, and displays course details and prerequisites.

What was the problem you were solving in the projects for this course?

The projects focused on organizing course information for an academic advising system. In Project One, I compared data structures and analyzed their runtime and memory requirements. In Project Two, I implemented a C++ program to load course data, display an ordered course list, and search for individual courses and their prerequisites.

How did you approach the problem?

I started by breaking the requirements into smaller tasks, including loading files, storing course information, searching, and sorting. I compared vectors, hash tables, and binary search trees to understand their advantages and limitations. Understanding data structures is important because the way information is stored affects performance, memory usage, and how easily a program can support its required operations.

How did you overcome roadblocks?

Some challenges involved reading data from files, resolving compilation errors, and making sure the program produced the expected results. I worked through these issues by reviewing error messages, checking file paths and input formats, and testing individual parts of the program. Breaking problems into smaller steps helped me identify their causes and make corrections.

How has this project expanded your approach to designing software?

This project helped me think about efficiency before starting implementation. I learned to compare possible solutions, use pseudocode to organize my ideas, and consider how performance changes as the amount of data increases. I also developed a better understanding of the tradeoffs between fast searches, ordered output, and memory requirements.

How has this project changed the way you write maintainable, readable, and adaptable programs?

I became more intentional about using descriptive names, consistent formatting, and functions with clear responsibilities. Separating file loading, searching, and displaying information makes the program easier to understand and modify. Input validation and useful error messages also help make the program easier to use and maintain.
